## 2. 关键失败路径：通过针对性检查

新增 `web/src/safety.ts` 和 `tests/web-safety.test.ts`：钱包 ACTION_REJECTED/4001（含嵌套错误）识别；查询失败、未知余额、不完整同步、错误网络禁用写操作；交易前账号/数据集身份核对，防止旧身份继续签名。三项单元测试通过，但钱包拒签使用模拟错误对象，不宣称真实扩展拒签验收。

本轮浏览器实际观察：

- 未连接时不展示虚构的零余额，充值/退款禁用；无钱包扩展时显示明确说明。
- 会员 A 切 B：余额显示 B 的钱包 30000、额度 0，不沿用 A 的 2940。
- 本地切主网：清空签名账户，公共研究只读。
- 只停启动器拥有的 API，保留原 chain/web：已连接 A 但余额显示待核查，额度未知，充值/退款禁用，不能判断待确认申请。

最终 `npm run build` 通过 TypeScript 和 Vite；仅有包大小警告。不是全部钱包、竞态、权限、注入或可访问性组合的完备证明。
